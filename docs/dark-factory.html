Self-Healing Pipeline

Every failure path has an automated recovery mechanism

Workflow Failure

Failure Reporter catches it → adds pipeline-error → Orchestrator retries 2x → if still failing, marks blocked with failed log excerpt.

Needs Clarification

Architect or Designer has questions → needs-clarification → Orchestrator rolls back labels (including design-done) → human answers → pipeline resumes.

PR Rework Exhausted

Bug Check rejects → PR Rework fixes. Counter based on Bug Check failure comments (not label events). After 3 → blocked.

Stuck Items (11 patterns)

Pipeline Monitor runs every 15 min (skips when empty). Detects all stuck states: intake-done, refined, design-done, ready, tests-ready, rework, merge, and more.

Built-in Safeguards

Race Condition Guard

Issue Breakdown verifies labels via API (not event payload) before running. Prevents dual-trigger with Design Refinement.

Dedup Protection

Checks existing sub-issues before creating new ones. Prevents duplicate sub-issues on re-trigger.

JSON Validation

Breakdown output stripped of markdown fences, validated as JSON array. Invalid output → pipeline-error, not silent failure.

Silent Failure Detection

Every Claude-invoking workflow checks output exists and is non-empty. Missing output → pipeline-error label.

Force-Push Guard

AI Teammate checks for existing PR before creating branch. Prevents overwriting PR Rework commits on re-trigger.

Cascade Serialization

Test Cases and AI Teammate use shared concurrency groups. Sub-issues process one at a time, preventing merge conflicts.

  • 3 Create GitHub Project board azlo with statuses: Backlog, Ready for Architecture, Ready for Design, Ready for Development, In Development, Ready for QA, In QA, Done
